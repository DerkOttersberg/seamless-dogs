# Standalone 0.2.0 acceptance — 7 October 2026

All eleven current builds pass local acceptance against their final gameplay JAR
hashes. Hosted CI could not start because GitHub reports an account billing lock.
[Verified hosted run](https://github.com/DerkOttersberg/seamless-dogs/actions/runs/37596382924). Local and hosted results
are recorded separately. Publication receipts are recorded separately as well.

The supported matrix is 1.20.1 Fabric/Forge and 1.21.1, 26.2 and 26.3
Fabric/Forge/NeoForge. Seamless Dogs is standalone; SeamlessLib is not required.
Paw-to-face grooming is removed; chest grooming remains. All Rights Reserved.

Modern branches pass 21 common tests; legacy branches pass 22. Each loader passes
all eight native scenarios covering ownership, eligibility, cancellation, timing,
terrain and protection denial, settings permissions, persistence and single loot
generation. 1.20.1 additionally passes five complete native repetitions on both
loaders against unchanged gameplay bytes. Failed attempts are preserved.

Packaged tests use genuine installed clients and dedicated servers. Keyboard,
mouse and unbound petting controls are exercised through the native Controls
screen, including options persistence, old-binding rejection and prompt hiding.
The Client visuals settings button opens Minecraft's native Key Binds screen.
Bindings save through Minecraft options; mod Save/Cancel apply to mod settings.

Two clients exercise server authority, invalid requests, remote animation and
entity-bound sound, late tracking, owner/server preferences and saved cooldowns.
The saved world is restarted with production mods only. Separate lifecycle runs
cover dimension changes, death/respawn, disconnection and reconnect.

Captured animation sequences were reviewed for first person, both third-person
views, both hands, slim/classic player models, observers, adult/baby pets, eyes,
resource reload, paw placement and recovery. Legacy player overlays restore their
own prior offsets before each new pose, and native render checks reject growing
body/head offsets. On 1.21.1, settings labels render after the native background
blur; fresh captures check readability at large and paired-client window sizes.
Requested GUI scales 2–4 remain subject to Minecraft's minimum-size clamping.

Some legacy paired owner frames have dark terrain/model lighting. Detailed hand
contact in those runs is assessed using clear standalone and observer captures
of the same gameplay bytes, alongside native paired pose and recovery checks.
The capture review records identify the affected frames rather than adjusting
their exposure or treating them as clear visual evidence.

Legacy hand rendering uses ordinary additive callbacks and a single swing argument
modifier. The installed 1.20.1 Forge client exposed the synthetic `Args` class-loading
failure documented in [Mixin issue 584](https://github.com/SpongePowered/Mixin/issues/584).
The revised hooks preserve the hand pose and avoid that mechanism without adding
a runtime library. Fresh packaged checks cover startup and continuous hand recovery
on both legacy branches. Test-only resource-pack metadata matches each game line.

The installed Forge 52 client starts its event bus after the Quick Play callback.
Early automatic world opening skipped native command and loot reload listeners.
The 1.21.1 Forge fixture therefore opens/connects through Minecraft's normal title
flow after mod loading. It requires native command registration and exercises the
normal loot path; no fallback loot manager or gameplay workaround is installed.
Quick Play startup on this upstream loader is outside the accepted launch path.

Combined profiles exercise the available Seamless suite and the exact optional
renderer/protection builds listed in [compatibility](COMPATIBILITY.md). They check
real own/foreign claim denial and active shaders where matching builds exist.
1.21.1 NeoForge also has a separate accepted Embeddium profile. Every accepted
log is audited; there are no unclassified ERROR/FATAL events.

The [machine-readable acceptance record](acceptance-0.2.0.json) binds final hashes,
source commits, dependency pins, logs, QA artifacts and reviewed capture manifests.
Only evidence for those exact bytes counts. Earlier previews and 0.1.0 evidence
do not establish acceptance for the current release.

Private evidence is retained at `D:/SeamlessDogsProduction-20261006`. Test profiles
use fresh owned worlds, private Xvfb displays, bounded heaps, two CPUs and low
priority. Official installation libraries may be reused read-only from previous
Windows evidence. No user game or world is controlled. QA drivers are excluded
from gameplay JARs. The temporary WSL assets/cache are removed after testing.

Software rendering does not validate every hardware driver. Silent OpenAL checks
entity-bound events and engine playback; audible quality needs interactive tests.
Legacy native Controls screens log an empty default audio-device option against
the silent "No Output" backend. That exact diagnostic is classified only when
the same log confirms successful OpenAL initialization and sound-engine startup.
Only recorded optional protection/rendering builds are claimed. Other claims,
custom rigs and texture layouts need separate verification. Upstream beta loaders
remain beta. Install packaging rejects incomplete acceptance or changed hashes.
